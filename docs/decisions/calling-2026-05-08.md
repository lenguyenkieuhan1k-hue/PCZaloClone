# Quyết định kỹ thuật — Chiến lược nghe/gọi (2026-05-08)

> **Trạng thái:** Chốt sau khi audit thực tế Zalo Web + cân nhắc 5 hướng. Hướng khuyến nghị: **A + C kết hợp**, làm A trong sprint hiện tại, C là R&D song song.
>
> **Quyết định bởi:** Team ZaloMask. Cập nhật khi có dữ liệu telemetry mới về tỷ lệ user thực sự thử gọi.

---

## 1. Bối cảnh + ràng buộc

### 1.1 Hiện trạng kỹ thuật

- Kiến trúc app v2: Electron mở `chat.zalo.me` cho từng profile, mỗi profile dùng `BrowserWindow` với `partition` Chromium riêng + browser fingerprint riêng + proxy riêng.
- Người dùng ấn nút gọi trong UI của Zalo Web → Zalo server trả thông báo `"Tính năng này chỉ dành cho Zalo PC"`.
- Đã verify: đây là **giới hạn server-side của Zalo**, không phải bug renderer hoặc thiếu permission browser.

### 1.2 Vì sao Zalo Web không thể gọi (phân tích kỹ thuật)

Zalo gate chức năng gọi qua **3 lớp**, lớp nào cũng từ chối client web:

1. **Server signaling**: endpoint `/api/group/call/...` và `/api/v1/personal/call/...` kiểm tra `User-Agent` + cờ `client_type` đính trong session token. Nếu không phải `pc` hoặc `mobile`, server trả error code 1xxx-2xxx + thông điệp "PC only".
2. **Native module**: Zalo PC client dùng module gọi tích hợp (libZaloAudio, libZaloVideo) compile-in. Module này KHÔNG được nạp xuống bundle web bằng JavaScript → không có code WebRTC + signaling logic phía client web.
3. **Trust/permission**: ngay cả khi vá được lớp 1 + 2, Zalo còn cross-check `imei` + `device_fingerprint` được register lúc đăng nhập. Web client register với type `web`, không thể tự nâng lên `pc` mà không bị reject.

**Hệ quả:**

- Spoof user-agent → Zalo phát hiện qua signaling token type ✗
- Inject custom JS module gọi WebRTC trực tiếp → không có endpoint nhận → ✗
- Patch Zalo server → vi phạm ToS, không khả thi ✗

→ **Không có cách hợp lệ nào enable calling trên web**. Phải tìm hướng vòng.

### 1.3 Ràng buộc đã chốt

1. Không bypass giới hạn nghe/gọi của Zalo Web (đã thử, không khả thi + rủi ro vi phạm ToS).
2. Không phá flow đang chạy: chat multi-account, payment SePay, license, cloud sync, auto-update.
3. Ưu tiên giải pháp ship được trong production thực tế, không chỉ POC.
4. Giữ định vị sản phẩm: **"chat đa tài khoản"** là core value, không cần biến thành "phone system".

## 2. Bảng so sánh phương án

5 hướng đã cân nhắc:

| # | Hướng | Khả thi | Rủi ro | Thời gian | Bảo trì | UX |
|---|---|---|---|---|---|---|
| **A** | **Web chat + chuyển nhanh sang Zalo PC** | ★★★★ | Thấp | 2-3 ngày | Thấp | Tốt nếu user đã cài Zalo PC |
| **B** | Bridge/interop với Zalo PC (đa tài khoản v1 quay lại) | ★★ | Cao | 4-8 tuần | Rất cao | Phức tạp, dễ lỗi |
| **C** | Mobile companion app (Android + iOS) | ★★★ | Trung bình | 6-10 tuần | Trung bình | Tốt — phù hợp thói quen người Việt |
| **D** | VoIP/SIP riêng (Stringee, Twilio) thay cho Zalo | ★★ | Thấp tech, cao thị trường | 3-4 tuần | Thấp | Lệch core value — khách muốn nhận cuộc gọi Zalo |
| **E** | Zalo OA (Official Account) API | ★ | Cao thị trường | 2-3 tuần để PoC | Phụ thuộc Zalo OA | Chỉ cho doanh nghiệp, có phí riêng |

### 2.1 Chi tiết Hướng A — Quick-switch sang Zalo PC

**Cách hoạt động:**

1. User mở chat trong ZaloMask → bấm nút gọi.
2. ZaloMask intercept event "PC only" → pop modal: *"Web không gọi được. Mở trên Zalo PC?"*
3. 3 nút: **Gọi qua Zalo PC** / **Gọi qua điện thoại** / **Hủy**.
4. "Gọi qua Zalo PC": ZaloMask phát hiện Zalo PC đã cài chưa.
   - Đã cài → launch Zalo PC qua deeplink `zalo://chat?uid=<peerId>` (deeplink Zalo PC support sẵn).
   - Chưa cài → show "Cài Zalo PC tại https://zalo.me/pc".
5. "Gọi qua điện thoại": tạo deeplink `zalo://chat?uid=<peerId>` → user click trên điện thoại → mở Zalo trên phone → tự bấm gọi.

**Hạn chế thực tế:**

- Zalo PC chỉ chạy 1 tài khoản tại một thời điểm. Nếu user đang chat 5 profile trong ZaloMask, gọi qua PC chỉ chuyển sang đúng tài khoản đang login trên Zalo PC. Phải hướng dẫn user "Gọi → tài khoản A" thì login Zalo PC bằng tài khoản A trước.
- → **Trade-off chấp nhận được**: 80% user gọi từ 1 tài khoản chính. ZaloMask vẫn là "nơi quản lý chat đa account", Zalo PC làm "cầu gọi cho tài khoản đang focus".

**Điểm cộng:**

- Triển khai nhanh (vài ngày).
- Không phụ thuộc dịch vụ ngoài.
- Không vi phạm Zalo ToS.
- UX dễ giải thích cho khách: "Chat chỗ này, gọi chỗ kia".

### 2.2 Chi tiết Hướng B — Bridge Zalo PC

**Ý tưởng:** Quay lại kiến trúc v1 (Windows user clone) cho mỗi profile, nhưng thay vì chạy Zalo PC luôn, chỉ launch khi user thực sự cần gọi → tận dụng call stack native của Zalo PC.

**Vấn đề thực tế:**

1. Zalo PC bound cookies vào Windows user (DPAPI). Phải tạo Windows user con cho mỗi profile → cần Admin permission, một số khách dùng máy công ty không cài được.
2. Zalo PC update thường xuyên + có anti-tamper. Mỗi bản update có thể vỡ bridge.
3. Single-active-session: khi mở Zalo PC cho profile A trong khi web ZaloMask đã login profile A → server kick web. User phải accept "1 tài khoản chỉ active 1 client".
4. Latency cao: người gọi đợi 5-10s để launch Zalo PC, trong khi điện thoại nhận cuộc gọi tức thì.

**Đánh giá:** Tech khả thi nhưng maintenance cost rất cao. **Không khuyến nghị làm chính thức**, chỉ giữ làm phương án backup nếu Hướng A không đủ.

### 2.3 Chi tiết Hướng C — Mobile companion

**Cách hoạt động:**

1. User cài app `ZaloMask Companion` trên Android (sau là iOS).
2. App đăng nhập cùng tài khoản ZaloMask Cloud (license của user).
3. Trên desktop ZaloMask, khi cần gọi → bấm "Gọi qua điện thoại" → server gửi push notification đến điện thoại user.
4. App mobile nhận push → bật notification "Gọi {tên contact}" + nút "Mở cuộc gọi".
5. User bấm → Companion app launch deeplink `zalo://chat?uid=...` → Zalo gốc trên phone mở → user bấm gọi.
6. Cuộc gọi thực tế chạy trên Zalo gốc (đã có sẵn của user). Companion chỉ là cầu nối UX.

**Note quan trọng:** Companion **không chạy cuộc gọi**. Chỉ relay deeplink + push notification. Cuộc gọi luôn ở Zalo official.

## 3. Khuyến nghị: A ngay, C song song R&D

### Vì sao A + C, không phải A + B?

- **A + C** giải quyết 95% nhu cầu khách: A dành cho user cài Zalo PC (giải pháp nhanh), C dành cho user thuần điện thoại + multi-device (giải pháp chuẩn dài hạn).
- **B** maintenance cost quá cao + dễ vỡ.

### Lộ trình triển khai

```
Tuần 1:    Ship Hướng A
Tuần 2-3:  Đo demand qua telemetry → quyết ưu tiên C
Tuần 4-6:  R&D Companion Android
Tuần 7-10: Port iOS
Tuần 11+:  Public launch
```
